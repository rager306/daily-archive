# Pipeline Script Architecture Acceptance

This directory contains M122 migration evidence for moving recurring pipeline scripts behind package use cases, ports, and infrastructure adapters while preserving compatibility entrypoints.

## Primary acceptance artifact

- `acceptance-summary.json` — generated by `uv run python scripts/run_pipeline_architecture_acceptance.py --summary data/pipeline-script-architecture/acceptance-summary.json`.
- `acceptance-ingest-report.md` — offline/no-index ingest report emitted by the catalog ingest wrapper during acceptance.
- `script-inventory.json` — S01 inventory of recurring pipeline scripts and migration ownership.

## Accepted wrapper pipeline

The acceptance runner exercises migrated compatibility entrypoints in dependency order:

1. `scripts/ingest_to_canonical_catalog.py --no-network --no-index`
   - Proves catalog-ingest wrapper can run offline without index mutation.
   - Writes `data/pipeline-script-architecture/acceptance-ingest-report.md`.
2. `scripts/replay_r024_218_document_parser_chunking.py`
   - Proves parser replay delegates through the application use case and infrastructure adapters.
   - Expected M121/R024 result: `221 total`, `219 ok`, `2 skipped`, `0 errors`, `2576 chunks`.
3. `scripts/build_r024_218_document_networkx_probe.py`
   - Proves graph probe delegates through the application use case and NetworkX adapter.
   - Expected M121/R024 result: `219 corpus_size`, `2 skipped_metadata_only`, `3891 nodes`, `10102 edges`, `6212 citation_relations`.
4. `scripts/build_r024_coverage_report.py`
   - Proves coverage report delegates through the coverage use case and filesystem report writer.
   - Expected M121/R024 result: `221 catalog_records`, `219 source_backed_records`, `2 metadata_only_records`, `0 parser_errors`.

## Architecture boundary checks

Run:

```bash
uv run python scripts/verify_onion_layering.py
```

The guard scans `src/research_graph/domain` and `src/research_graph/application`. Domain must not import application, infrastructure, workflows, CLI, or scripts. Application must not import infrastructure, workflows, CLI, or scripts. Infrastructure remains allowed to depend inward on application/domain contracts.

## Post M122 mutation gate

Run the focused mutation gate after changing M122 application-layer accounting logic:

```bash
uv run pytest --gremlins \
  tests/test_corpus_coverage_use_case.py \
  tests/test_graph_probe_use_case.py \
  tests/test_parser_replay_use_case.py \
  tests/test_m122_property_mutation_guards.py
```

The gate is scoped in `pyproject.toml` to critical application modules and writes a JSON report to `coverage/gremlins/gremlins.json` (ignored by git). A passing run should report `survived=0`, `error=0`, and `pardoned=0`. Keep `archive/` and `.agents/` outside this project-scoped quality gate unless a future milestone explicitly expands scope.

The deterministic fallback smoke check remains available for agents or CI surfaces that cannot run pytest-gremlins:

```bash
uv run python scripts/run_m122_mutation_smoke.py --json
```

## Intentionally out of scope

These scripts remain deliberately outside the S06 integrated M121-style acceptance path:

- `scripts/extract_r024_quality_metrics.py`
- `scripts/extract_r024_20_document_quality_metrics.py`
- `scripts/extract_r024_53_document_quality_metrics.py`
- `scripts/extract_r024_entity_quality_metrics.py`

Reason: `quality-metrics` remains a first-class migration category and must not be folded into coverage/reporting. It is tracked separately in `script-inventory.json`.

- `scripts/build_r024_entity_networkx_probe.py`

Reason: entity-scale probing is a separate historical graph-probe variant outside the bounded 218-document M121 acceptance replay used to close M122. It remains visible in `script-inventory.json` for future entity-scale migration or explicit de-scope review.

## Diagnostic policy

Acceptance artifacts should contain paths, phase names, counts, durations, exit codes, and reason-coded failures only. Do not add corpus body text or article payload values to diagnostics.
