Идеи: независимый Rust-crate для разбора научных статей

Дата: 2026-08-26 Тема: pure-rust-scholarly-parse-crate Режим: этот репозиторий — плоскость разбора научных PDF
Фокус: не декорации. Постепенно вынести существующий Rust-функционал разбора (аналог GROBID + вся обработка PDF/HTML) в независимый crate с контролем по API crate; реализовать глубину GROBID на Rust; база — фишки ruVector (SIMD, SMP, арены, HNSW, paged), не только SONA. codebase-memory-mcp.

Контекст обоснования

Репозиторий. Разбор научных статей уже написан на Rust, но размазан по onion и не является crate. Workspace-члена da-parse нет. Индекс 2026-08-19 (metadata-changed / not_tracked на parse-файлах — claims сверены исходником). В da-adapters: GrobidParser (~3,5k, HTTP :8070 + string-lift TEI), HtmlParser (тот же string-скан секций, tei_xml: None), feature-gated pdf_classifier / region_text (pdf-inspector), клиент pdffigures2. В da-domain уже лежат parse-типы вне adapters: XY-Cut LineBox, TeiFigure (M451, regex по TEI), HtmlSection, pdf_toc, pdf_classification. В da-ports — ParsedArticle без authors / article-idno / индекса нетабличных фигур; layout_json всегда None. Application оркестрирует ingest, кэш, fail-open grammar_route. Это и есть «существующий функционал»: его выносят, а не рисуют фасад вокруг Java.

Боль. M463: 2608.22118 authors TEI=1 / поля lift нет; нетабличные фигуры 48 / 0 при том, что TeiFigure уже умеет считать <figure>. eval_batch Micro-F1 ~0.87 зелёный. Coords figure,table,note,formula запрашиваются и ампутируются. Второй JVM — pdffigures2. GrobidParseStage отпечатывает rich consolidate*=1 при наличии structural(). vendor GROBID ~166k узлов полного каскада. grobid-rs = JNI + pdfalto GPL-3. Workspace уже тянет ruvector-sona / hybrid / gnn-rerank / agent-memory / solver / rvf — не на parse-пути. В ruvector (~351k узлов) лежат не только SONA: SIMD (ruvector-cnn, prime-radiant), арены (ruvector-core, QueryArena), paged attention (ruvllm), HNSW (ruvector-core index/hnsw), SciPix — math OCR + SIMD/arena, не TEI-каскад.

Замки. D127: TEI ≠ истина графа. Лук: application не зависит от adapters; новый crate реализует ParserPort, не kg-parse. Не форкать pdfalto/PDFium в runtime — контракт LayoutToken и reading-order берём (идея 4). Не считать MinerU TEI-продуктом, паттерны таблиц/layout можно читать. Обучение контура открыто; продвижение — conservation (идея 2). Не строить пустой фасад :8072. Чужие реализации не выбрасывать: оценить → адаптировать на Rust.

Снаружи и доноры (этот проход). Чужие реализации не отбрасываем: оцениваем → берём контракт/паттерны → адаптируем на Rust с SIMD/аренами/SMP ruVector, либо ищем более элегантный аналог. GROBID: модели работают на Layout Tokens (Unicode + шрифт/стиль + bbox), не на голом тексте; pdfalto даёт ALTO + XY-проекции линий/блоков/колонок — контракт IR, не обязанность форка C++. ScienceBeam — Python-порт каскада (уроки переписывания, не runtime). Уже в репо: XY-Cut из Java opendataloader-pdf → LineBox. oxidize-pdf / pdf_oxide — pure-Rust spatial text, bbox, у pdf_oxide 4 стратегии reading order включая XY-Cut; продукт RAG/markdown, паттерны токенов годны. LiteParse — PDFium C++: не зависимость runtime, алгоритм reading-order можно читать. Не считать их TEI-движком. SciPix — OCR формул, не TEI.

Поправка верификатора (нагрузка). PdfProcessResult из classify-time process_pdf_mem не отдаёт TextItem/TextLine/PdfRect — «собрать Full, который уже платим» в решётку токенов перечитывает API. data/gold_standard — 193 файла entity-gold, не 193 TEI (закоммиченные TEI-инвентари — две статьи). grammar_route работает до lift, поэтому коэффициенты консервации не могут быть его входом на первой консультации.

LLM / агенты / место ruVLLM+SONA (этот проход). Развилка: N специалистов как GROBID + FSM-оркестратор против одной большой модели + FSM. Индекс grobid: EngineParsers — ленивый реестр Segmentation, Header(+Flavor), AffiliationAddress, Author, Date, Citation, ReferenceSegmenter, FullText, Figure, Table, Funding…; GrobidModels — папка на каждую модель, flavors = те же парсеры, другие веса. ruvector SONA: apply_micro_lora(&[f32], &mut [f32]) — адаптер скрытого вектора rank 1–2, не sequence labeler; вход траектории — query_embedding. ruVLLM — GGUF-runtime (пример в README: Qwen2.5-7B) с SONA на generation; training-модуль учит роутинг агентов Claude Flow (13 типов) и выбор Haiku/Sonnet/Opus, не BIO-лейблы TEI. FSM daily-archive: пять DecisionPoint (grammar_route, admission, concurrency, retry, summary_depth) на ArticleFeatures без сырого текста — оркестратор, не таггер. Вердикт: baseline crate = специалисты + FSM, сейчас без LLM. ruVLLM — критик и учитель на этапе отладки/обучения (Gauntlet train-path), не processFulltext. Позже функционал crate можно расширить LLM-остатком; агентский флот не baseline parse.

Оси темы

  • Граница crate — вынос существующего Rust PDF/HTML/TEI-lift в da-parse, не зонтик ingest/граф
  • Фундамент layout-токенов — пространственный текст, reading order, bbox до каскадной разметки
  • Паритет каскада GROBID — существующий lift → нативные стадии → TEI/coords; API crate как контроль
  • Движок ruVector — SIMD / SMP / арены / HNSW / paged; SONA Instant/Background/Deep как один контур, не весь набор
  • Офлайн-проверка Gauntlet — gold TEI, метрики консервации, не один entity F1

Карта GROBID → проекция на da-parse

Снято с FullTextParser.processing (строки 145–442), HeaderParser.processingHeaderSection (137–396), EngineParsers, GrobidModels, SegmentationLabels. Это карта донора, не план реализации.

Каскад processFulltext (ядро качества)

pdfalto → LayoutToken → Segmentation (зоны: cover, header, body, references, annex, page, headnote/footnote/marginnote, acknowledgement, funding, availability, toc, conflict, contribution) → Header(flavor) на зоне header → AuthorParser (names/header) + sanityCheck + deduplicate → AffiliationAddressParser + attachEmails + preLinkByPrecedingAuthorCluster + attachAffiliations → DateParser (normalize pub/sub/download/server) → language id · dehyphenize · keywords · DOI-from-doc → consolidateHeader (опционально, Crossref) → abstract ещё раз через fulltext/shorttext → CitationParser.processingReferenceSection + ReferenceSegmenter → consolidateCitations пачкой (опционально) → Fulltext label body → FigureParser / TableParser / EquationParser → revert bad figures/tables в paragraph → то же на annex (та же fulltext-голова) → postProcessCallout (bibr vs footnote superscript) → toTEI (body+annex+header+figures+tables+equations+markers+coords)

Отложить на фазы — не отказаться

Native подменяет стадию, когда conservation проходит. Расширения (patent, flavors, Crossref, language) включаются отдельной фазой, не ломая контракт.

1. da-parse: вынести существующий Rust-разбор PDF/HTML/TEI

Уверенность 93% Сложность средняя Ось: граница crate
Описание
Продукт — рабочее имя da-parse: независимый crate, в который переезжает уже написанный Rust-разбор научных статей, а не пустой фасад. Переезд поэтапный, не big-bang dump одного файла: (1) TEI-lift из GrobidParser (extract_title/abstract/body/sections/citations/tables/formulas) + типы TeiFigure из domain; (2) HtmlParser + HtmlSection; (3) pdf-classifier / region_text; (4) потребитель XY-Cut LineBox (геометрия может остаться нейтральным типом в domain). Описание
