Abstract
The application of large language models (LLMs) in the field of coding is evolving rapidly: from code assistants,
to autonomous coding agents, and then to generating complete projects through natural language. Early LLM
code benchmarks primarily focused on code generation accuracy, but these benchmarks have gradually become
saturated. Benchmark saturation weakens their guiding role for LLMs. For example, HumanEval Pass@1 has
reached 99.4% and MBPP 94.2%. Among various attempts to address benchmark saturation, approaches based
on software engineering have stood out, but the saturation of existing software engineering benchmarks is rapidly
increasing. To address this, we propose a new benchmark, Web-Bench 12 , which contains 50 projects, each
consisting of 20 tasks with sequential dependencies. The tasks implement project features in sequence, simulating
real-world human development workflows. When designing Web-Bench, we aim to cover the foundational elements
of Web development: Web Standards and Web Frameworks. Given the scale and complexity of these projects,
which were designed by engineers with 5 to 10 years of experience, each presents a significant challenge. On
average, a single project takes 4 to 8 hours for a senior engineer to complete. On our given benchmark agent
(Web-Agent), SOTA (Claude 3.7 Sonnet) achieves only 25.1% Pass@1, significantly lower (better) than SWEBench’s Verified (65.4%) and Full (33.8%) scores. Finally, we discuss that in any development field, Standards and
Frameworks represent foundational knowledge and efficiency tools, respectively, and LLMs require optimization
tailored to them.

1. Introduction
The application scope of large language models (LLMs)
is constantly expanding and already includes fields such
as chatbots, search, and scientific research. Applications in the field of coding are also evolving rapidly,
from basic code assistants [1, 2], to autonomous coding
agents [3], and then to attempts to generate complete
projects through natural language [4, 5]. Although it is
still in the early stages of exploration, the potential of
LLM coding is already evident despite limited practical
results.

Existing software engineering benchmarks, such as
SWE-Bench [22] and RepoBench [20], both use independent tasks to organize datasets. Although the data
in these benchmarks may come from real projects, the
tasks themselves lack coherence and differ significantly
from real-world development workflows. This paper
proposes a new benchmark, Web-Bench, which contains 50 projects, each consisting of 20 tasks with sequential dependencies. The tasks implement project
features in sequence, simulating real-world human development workflows. When designing Web-Bench, we
aim to cover the foundational elements of Web development: Web Standards and Web Frameworks. Web
Standards are basic knowledge of Web development and
cover CSS Selector, CSS Layout, DOM, SVG, WebGL,
ECMAScript [23], TypeScript [24], etc. Web Frameworks provide higher-level abstraction capability and
improve development efficiency, covering key aspects of
Web development such as UI Framework [25], State
Management [26], CSS Framework, Fullstack Framework, ORM, Build, etc.

Early LLM code benchmarks focused on the accuracy
of code generation, but these benchmarks have gradually become saturated: HumanEval [6] SOTA 99.4%
[7] and MBPP [8] SOTA 94.2% [9]. Benchmark saturation weakens their guiding role for LLMs. To solve
this problem, many new ideas have emerged, such as
increasing programming languages [10, 11, 12], increasing test coverage [13, 14], increasing dataset complexity
[15, 16, 17, 18], and improving software engineering reproducibility [19, 20, 21, 22]. We prefer to find a method
that can measure the actual complexity of codes. This
means that the benchmark should cover the coding process as much as possible and be close to real projects in

2.2.2 Framework
In the early stages of Web development, there were
not many development frameworks, and various Web
applications could be developed using native technologies. However, with the rise of Web 2.0, both the technical complexity and application scale of Web applications have increased dramatically, and the development efficiency based solely on native Web technology has been challenged. Development frameworks
have brought greater abstraction capabilities, improved
development efficiency, and enhanced collaboration to
Web development, covering its main aspects:
• UI Framework: Usually provides a componentbased development model and supporting development tools to improve the efficiency of singleunit development and collaboration, such as React,
Vue, Angular, Threejs, etc.

Figure 4: All Standards and Frameworks in Web-Bench
• TypeScript: A strongly typed programming language that builds on JavaScript.
TypeScript
code converts to JavaScript, which runs anywhere
JavaScript runs. Most modern web applications
are now built with TypeScript.

• State Management: UI state management is one
of the core tasks in Web application development.
Excellent frameworks will simplify the state model
and improve development and maintenance efficiency, such as Redux, Zustand, Jotai, Mobx, etc.

• CSS Selector: Patterns that match against elements in a tree and are one of the core technologies
used to select nodes in a document.

• CSS Framework: Improves CSS maintainability
and development efficiency by enhancing basic capabilities such as variables, modules, functions, or
providing CSS utilities. Examples include SASS,
LESS, Stylus, Tailwind, etc.

• Flexbox: A layout model that arranges items in
one dimension. The children of a flex container
can be laid out in any direction, and can "flex"
their sizes, either growing to fill unused space or
shrinking to avoid overflowing the parent. It is
widely used in most web applications.

• Build:
Web applications eventually run in
browsers, and during the development phase, JS
code and various resources (CSS, images, icons
etc.) are usually split into many modules (or files),
which require modular packaging using build tools,
as well as optimization such as merging and compression. At the same time, build tools are also
required to unify the development experience —
handling JS syntax conversion, CSS preprocessing,
and integration of various tools (including linting,
formatting, testing frameworks, etc.) — such as
Webpack, Vite, Parcel, etc.

• Grid: A two-dimensional grid-based layout system.
The children of a grid container can be positioned
into arbitrary slots in a predefined flexible or fixedsize layout grid. It is more powerful than flexbox
and also widely used in web applications.
• DOM (Document Object Model): defines a platform neutral model for events and node trees. It is
the main technology used to manipulate web page
elements.
• SVG (Scalable Vector Graphics): An XML-based
language for describing two-dimensional graphics.
SVG drawings can be interactive and dynamic.
Animations can be defined and triggered declaratively.

• Fullstack Framework: Fullstack usually refers to
the ability of developers to handle both front-end
(such as UI) and back-end (such as data and logic
processing) development. In this context, it refers
to frameworks that support both front-end and
back-end development, such as Next.js, Nuxt, Express.js, etc.

• Canvas: Used for drawing graphics via JavaScript
and the HTML <canvas> element. It can be used
for animation, game graphics, data visualization,
photo manipulation, and real-time video processing.

• Database Framework Data management is a relatively independent and core part of back-end logic.
Data can be managed directly via SQL using tools
like SQLite, or through object-relational mapping
frameworks such as Prisma and Sequelize.

• WebGL (Web Graphic Language): An immediate
mode 3D rendering API designed for the web. It

5. Related Work
Early LLM code benchmarks focused on the accuracy
of single-function code generation. We review several
widely cited benchmarks:
• HumanEval [6]: 164 handwritten Python coding
questions are used to evaluate functional correctness. Each question contains a function signature,
docstring, and function body, and has an average
of 7.7 test cases.
• MBPP [8]: About 1,000 entry-level crowd-sourced
Python coding questions covering coding basics
and standard library functions, with each question
having an average of 3 test cases.
• APPS [29]: 10,000 Python coding questions—5,000
for training and 5,000 for testing—sourced from
multiple coding competition websites, covering
simple problems, technical interview questions,
and algorithm competition-level challenges. Each
question has an average of 13 test cases.

5.3 Increasing dataset complexity
The problems in the early code benchmarks contain
many basic algorithms, which are no longer challenging
for LLMs; increasing the complexity of a single problem
is also an idea.
• DS-1000 [15] is a code generation benchmark containing 1,000 data science problems, covering seven
Python libraries such as NumPy and Pandas. The
problems come from Stackoverflow and have been
lightly edited.

5.1 Increase programming languages
Most of the problems in early code benchmarks used
Python as the programming language. In addition to
Python, mainstream languages in real-world development include C++, JavaScript, Java, Go, etc., making
it natural to consider expanding language coverage.

• HumanEval-X [11] extends the HumanEval benchmark to Python, C++, Java, JavaScript, and Go
via human translations

• CoderEval [16] contains 230 Python and 230 Java
code generation problems carefully selected from
popular open source projects. It supports code
generation problems with six different levels of context dependency. It supports problems with six
levels of context dependency, and performance is
significantly better when generating independent
functions compared to non-independent ones.

• HumanEvalPack [12] extends the HumanEval
benchmark to cover three coding tasks—code
repair, code interpretation, and code generation—and six languages (Python, JavaScript, Java,
Go, C++, Rust) via human translations. As shown
in Table 3, the SOTA in 2024 has reached 78%.

• BigCodeBench [17] combines tools from 139 libraries across 7 domains to support 1,140 finegrained tasks.
It integrates multiple existing
benchmarks and enables the implementation of
functions such as data analysis and web development by calling multiple tools.

• MultiPL-E [10] translates HumanEval and MBPP
to 18 other programming languages.

• MLE-bench [18] is a benchmark for measuring the
performance of AI agents in machine learning engineering tasks. 75 ML engineering competitions
were selected from Kaggle to evaluate real-world
skills such as model training, dataset preparation, and running experiments for machine learning workflows. As shown in Table 3, the current
SOTA is only 16.9%. As the coding capabilities
of LLMs continue to improve, such professionally
oriented benchmarks are expected to become more
prevalent.

7. Limitation
Web 2.0 has brought about the rapid development of
the Web development ecosystem. Dating back to 2005,
nearly two decades have passed. Although the current version of Web-Bench covers the core Standards
and Frameworks, many others remain uncovered due
to workload constraints. In the future, we will strive
to cover more standards and frameworks by innovating
project design and development tools.
