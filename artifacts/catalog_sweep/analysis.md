## Что докрутить (по убыванию эффекта)

1. **Rule-based extractor слеп к не-CS лексике** — 3 статьи с 0 entities
   (math-oc, robotics). Расширение `methods.phrases` DATA-словаря
   (M313-паттерн) закроет их без кода. Ожидаемый эффект: +0.5% покрытия
   корпусом извлечения; для полного каталога это ~десятки статей.
2. **Параллелизм GROBID** — cold p95 20.4s при workers=4; GROBID CRF держит
   6-8 параллельных запросов. Workers=8 сократит полный холодный прогон
   с ~34 до ~17 мин. Проверить память контейнера (-Xmx4g).
3. **Embed-стадия доминирует в cold-тайминге** (~0.5-1s на статью FD_API
   CPU). Для будущих полных перегенераций — батчевый embed-endpoint
   (если FD_API поддерживает) или локальная модель.
4. **Resume-семантика отчёта** работает (405 кэш-хитов после паники),
   но первый прогон потерял 606 записей из-за panic в worker join.
   Добавить per-article crash-safe flush (каждые N записей — partial write)
   чтобы повтор после паники не перекачивала кэш заново (здесь спас кэш).
5. **9 source-аномалий** — точки роста acquisition: 8 no_pdf (нужен
   HTML-путь через HtmlParseStage — уже существует) и 1 no_source_dir
   (2605.29548 — переаквизиция).

## Найденный продуктовый баг (исправлен в этой волне)

`rule_extractor.rs` резал текст по байтовым индексам из lowercase-копии —
паника на мультибайтных символах ('µ') роняла весь свип (worker join).
Исправлено char-boundary snapping + red-first регресс-тест с мутационной
проверкой. Это чинит extraction любых не-ASCII текстов (франц., нем. символы
в body text).
