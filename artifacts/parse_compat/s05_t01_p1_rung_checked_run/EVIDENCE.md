## What this repair changed

Scope was exact and narrow. No engine, dependency, graph, import, download,
promotion, regional-repair or Java activation; routing and locks are unchanged.

1. **The P1 plane path now has a checking entry point.**
   `localize_body_plane` was a public pure helper that never compared the
   inventories' `BodyUnitRung` (normalization ladder + case policy). The body path
   (`classify_body_coverage`) checked rungs; the P1 path did not, so a plane and an
   oracle tokenized at different rungs could be localized silently at the wrong
   rung. Now:
   - `localize_body_plane_checked` is the public P1 entry point: it refuses a pair
     whose `rung()` differs with the new typed error
     `NativeBodyTextError::PlaneOracleRungMismatch`;
   - the algorithm moved to the private, documented `localize_body_plane_unchecked`
     (both inventories must already sit at the same rung); the public unsafe path
     is gone.
2. **The detached probe uses the checked API.**
   `crates/da-cli/examples/native_body_character_probe.rs` now calls
   `localize_body_plane_checked(&plane_units, &oracle_units)?` instead of the
   unchecked helper.
3. **Negative tests pin the refusal.**
   `crates/da-parse/tests/native_body_character_oracle.rs` adds
   `a_checked_plane_localization_refuses_a_normalization_rung_mismatch` (Raw vs
   normalized) and `a_checked_plane_localization_refuses_a_case_policy_mismatch`
   (CaseFolded vs CaseSensitive), each asserting
   `Err(NativeBodyTextError::PlaneOracleRungMismatch)`, and moves the five existing
   P1 tests onto the checked API (`expect("same-rung plane and oracle localize")`).
4. **The false cause assertion is removed, replaced by the truthful bucket fact.**
   Both live evidence documents previously asserted that the 69 400
   `uncertain_present_in_token` occurrences were "present as whole native tokens
   but cannot be bound monotonically" (an order mismatch). That is not what the
   bucket means: `contained_in_one_token` matches any side token that *contains*
   the occurrence, so the bucket merges occurrences equal to a side token
   (unanchored, e.g. the `repeated-the` case) with occurrences that are only a
   proper substring of one (e.g. `he` inside `the`). The counters do not separate
   the two, so no order-based cause is asserted. Corrected in
   `native_body_character_scope_bound.evidence.md` (which also points here as its
   superseding run) and in `native_body_character_scope_bound.repair2_run.evidence.md`.
   The originals are preserved byte-for-byte under `preserved_before/`.
   Splitting the bucket into separate equal/proper-substring counters was
   available as an alternative; the smaller truthful fix (remove the unsupported
   cause) was taken, and the evidence names the separation as future work.
